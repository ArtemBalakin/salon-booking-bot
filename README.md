# salon-booking-bot

Telegram-бот для записи клиентов (салон красоты) с Mini App для выбора услуги, мастера и времени.
Бэкенд — Spring Boot (Java 17), хранение — PostgreSQL, весь стек поднимается через docker-compose.

## Что умеет

**Клиент**
- Mini App: услуга → мастер (только те, кто выполняет услугу) → день/время → имя и телефон (маска `+7 (___) ___-__-__`).
- Подтверждение записи приходит в чат с ботом (услуга, мастер, время, адрес салона).
- `/my` или кнопка «Мои записи» — список предстоящих записей с кнопкой «Отменить запись».
- Напоминания в чат за 24 часа и за 2 часа до визита.

**Администратор (владелец, `ADMIN_CHAT_ID`)**
- Новая запись приходит с кнопками «✅ Подтвердить» / «❌ Отклонить»; клиент получает уведомление о решении.
  Отключается переменной `MANUAL_CONFIRMATION=false` (записи подтверждаются сразу).
- Уведомление, если клиент отменил запись.
- `/today` и `/tomorrow` — расписание на день.

**Система**
- Слоты автоматически добиваются на 14 дней вперёд каждую ночь (и при старте), прошедшее время не показывается.
- Отменённый/отклонённый слот снова становится свободным.
- Часовой пояс салона — `APP_TIMEZONE` (по умолчанию `Asia/Almaty`).

## Состав

- `bot-service/` — Java-приложение: REST API + Telegram-бот в одном сервисе
  - `src/main/java` — код (entity/repository/service/controller/bot)
  - `src/main/resources/db/migration` — Flyway-миграции: схема, демо-данные (2 мастера, 4 услуги), связь мастер↔услуга, статусы записей
  - `src/main/resources/static/miniapp` — Mini App (HTML/CSS/JS), раздаётся тем же Spring-приложением по пути `/miniapp/index.html`
- `docker-compose.yml` — Postgres + app
- `.env.example` — шаблон переменных окружения

## Быстрое подключение своего Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. **Windows PowerShell**: запустите из корня проекта:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
   ```

   Скрипт запросит токен **скрытым вводом**, username, chat ID администратора и название салона.
   Он создаст локальный `.env`, который **не попадает в Git**, и не выведет токен на экран.
   В качестве альтернативы можно вручную скопировать `.env.example` в `.env` и вставить `BOT_TOKEN=...`.
3. Запустите `docker compose up --build -d`. Без токена приложение запускает API и Mini App, а Telegram-бот отключён.
4. Когда выберете хостинг и получите публичный HTTPS URL, вставьте его в `APP_BASE_URL` в `.env`, затем перезапустите приложение (`docker compose up -d --force-recreate app`).

**Никогда не коммитьте `.env` или сам токен.** Если токен оказался в репозитории, замените его через BotFather. При запуске Maven напрямую `.env` автоматически не подхватывается: переменные нужно экспортировать в окружение; при `docker compose` они читаются автоматически.

**Внешний вид:** Mini App — адаптивный light-theme дизайн; название студии отображается через `SALON_NAME` (публичный `/api/public-config`). CSS-тема находится в `bot-service/src/main/resources/static/miniapp/css/styles.css` (`--accent`, `--background`, `--ink`). Никаких секретов в браузер конфиг не отдаёт.

## Как запустить

1. Скопировать `.env.example` в `.env` и заполнить:
   - `BOT_TOKEN` — получить у [@BotFather](https://t.me/BotFather) (`/newbot`)
   - `BOT_USERNAME` — username бота без `@`
   - `ADMIN_CHAT_ID` — chat_id владельца салона (узнать через [@userinfobot](https://t.me/userinfobot)); владелец должен сначала написать боту `/start`
   - `APP_BASE_URL` — публичный https-адрес, на котором будет жить приложение (для продакшена — адрес после деплоя, например на Railway)
   - `SALON_NAME`, `SALON_ADDRESS` — название и адрес для сообщений клиентам

2. Поднять стек:

   ```
   docker compose up --build -d
   ```

3. Проверить, что API отвечает: `http://localhost:8080/api/services` должен вернуть список из 4 демо-услуг.

4. Написать боту в Telegram `/start` — должна прийти кнопка «Записаться», открывающая Mini App.

> Важно: кнопка Mini App у Telegram-бота откроется только если `APP_BASE_URL` — настоящий **https**-адрес (Telegram не даёт открывать `http://localhost` внутри клиента). Для локальной проверки самого Mini App (без бота) можно просто открыть `http://localhost:8080/miniapp/index.html` в браузере — API будет работать, а Telegram-специфичные вещи (тема, initData) просто не сработают; создать запись без Telegram нельзя. Для полноценного теста кнопки бота на локальной машине можно прокинуть порт наружу через `ngrok` или сразу задеплоить на Railway/аналог.

## Сборка без Docker

Нужна Java 17:

```
cd bot-service
mvn clean verify
```

## Демо-данные

При первом запуске Flyway создаёт 2 мастеров и 4 услуги; слоты на ближайшие 14 дней (10:00–19:00, шаг 1 час) генерируются приложением.

| Мастер | Услуги |
|---|---|
| Айгерим | женская стрижка, мужская стрижка, окрашивание |
| Динара | женская стрижка, маникюр (гель-лак) |

Перед реальной эксплуатацией демо-данные нужно заменить на настоящие услуги/мастеров (прямыми SQL-запросами в `service`, `master`, `master_service`; отдельной админки пока нет). Часы работы — `salon.work-start-hour` / `salon.work-end-hour` в `application.yml`.

## Дизайн

Основные цвета Mini App вынесены в CSS-переменные в `src/main/resources/static/miniapp/css/styles.css`:

```css
--accent: #a75d4c;     /* кнопки, выделения */
--background: #f9f6f1; /* фон */
--ink: #332b28;        /* текст */
```

Для реального салона достаточно указать `SALON_NAME` и, при желании, поменять CSS-переменные, чтобы адаптировать оформление к бренду. Интерфейс специально оформлен светлой темой, не зависит от цветовых настроек Telegram.

## Известные ограничения

- Длительность услуги не влияет на расписание: слот всегда один час.
- Нет веб-админки и переноса записи (только отмена и повторная запись).

## Продакшен

Перед передачей бизнесу — регистрировать хостинг (Railway/VPS) и `BOT_TOKEN`/домен нужно на аккаунте заказчика, а не разработчика.

## Результаты аудита и ограничения перед продакшеном

- Telegram Mini App `initData` проверяется по подписи **и времени** (`auth_date`, максимум 24 часа); неавторизованная запись отклоняется.
- Имена мастеров/услуг отображаются через `textContent`, без вставки HTML из базы.
- Защищены от устаревших ответов одновременные загрузки слотов и мастеров; ошибки загрузки показываются пользователю.
- Сервер поддерживает переменную `PORT` для PaaS; `APP_BASE_URL` обязательно должен указывать на публичный HTTPS-домен.
- `BOT_TOKEN`, `DB_PASSWORD` и другие секреты — только в переменных окружения; реальные `.env` исключены из Git.
- Текущая модель календаря работает с **часовыми слотами**, не блокирует соседние слоты для услуг 90/120 минут: **не использовать для коммерческих записей, пока не исправлено**.
- Telegram-уведомления и напоминания пока отправляются без устойчивой очереди/outbox: при сбое Telegram возможна потеря сообщения.
- Используется long polling и планировщик в одном экземпляре сервиса — **запускать только одну реплику**, иначе возможны дубли.
- Демо-мастера и услуги загружаются миграцией: перед подключением реальных пользователей нужно заменить данные и согласовать график мастеров, выходные и буферы.
- Данные клиентов (телефоны) требуют контроля доступа, политики хранения и резервных копий БД.

## Деплой на PaaS (Railway/Render и др.)

Для Docker-сервиса укажи путь до `bot-service/Dockerfile`, контекст сборки `bot-service`, наружный HTTPS-адрес сервиса в `APP_BASE_URL`.
Задай `BOT_TOKEN`, `BOT_USERNAME`, `ADMIN_CHAT_ID`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `APP_TIMEZONE=Asia/Almaty`, `MANUAL_CONFIRMATION`, `SALON_NAME` и `SALON_ADDRESS`.
На PaaS создай **постоянную** PostgreSQL (не эфемерный диск), настрой резервные копии и только одну реплику приложения.
`PORT` обычно задаёт сам провайдер; локально по умолчанию 8080.

**Важно:** Render/Koyeb free засыпают без входящих HTTP-запросов, что несовместимо с непрерывным long polling и планировщиком напоминаний. Для работающего бизнеса используй always-on тариф/VPS.
